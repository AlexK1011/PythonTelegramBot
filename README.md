# PythonTelegramBot

Telegram-бот, который следит за постами в чужих каналах и присылает пользователю
только те, которые "выстрелили" - набрали высокий процент репостов относительно
просмотров. При желании пост перед отправкой можно прогнать через ИИ
(переформулировать/оформить по правилам пользователя).

## Как это работает

1. Пользователь пересылает боту сообщение из канала - канал добавляется в список
   отслеживаемых для этого пользователя.
2. Фоновая задача (services/monitor_channels.py) периодически проверяет все
   отслеживаемые каналы на новые посты через userbot-клиент (Pyrogram).
3. Для каждого нового поста (services/post_processor.py) считается доля
   репостов от просмотров. Дальше - в зависимости от режима пользователя:
   - Отложенная проверка (delayed_check) - бот ждёт заданную задержку,
     чтобы пост успел набрать статистику, затем проверяет процент репостов и,
     если порог пройден, отправляет пост пользователю.
   - Периодический сбор (periodic_collection,
     services/periodic_collector.py) - раз в заданный интервал собирает все
     новые посты и отправляет топ-N самых репостнутых.
4. Если у пользователя включён ИИ, текст поста перед отправкой обрабатывается
   через внешний API (services/send_to_ai.py, сейчас - gen-api.ru,
   модель deepseek-v3) по системному промпту и пользовательским правилам
   форматирования.

## Структура проекта

- main.py - точка входа, запуск бота и фоновых задач.
- handlers/ - хендлеры aiogram (команды, добавление/удаление каналов, меню настроек).
- services/ - вся бизнес-логика: мониторинг каналов, обработка постов, запросы к ИИ.
- core/ - конфиг, работа с БД (SQLite), настройка логирования.
- utils/ - вспомогательное: клиенты ботов, клавиатуры, форматирование времени, чистка логов.

## Технологии

- aiogram - обработка команд/колбэков от обычного бота (у которого есть только токен).
- Pyrogram (userbot, API_ID/API_HASH) - используется отдельно, только для
  чтения истории и статистики чужих каналов, куда обычный бот-токен доступа не имеет.
- SQLite - хранение каналов, подписок пользователей и их настроек.
- FSM-состояния диалогов хранятся в памяти процесса (MemoryStorage), без внешних БД.
